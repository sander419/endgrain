# Как устроен End-Grain Compiler

Документ для того, кто будет добавлять в проект новое — включая меня через полгода.
Здесь правила, которые не видны из кода: где чему место, что чем проверяется
и почему сделано именно так.

## Четыре правила, из которых следует остальное

1. **Ни одного числа без первоисточника.** Всё, что показано пользователю как факт,
   либо взято из справочника со ссылкой и датой сверки, либо помечено как оценка.
   Не нашли данных — так и пишем, а не подставляем правдоподобное.
   Подробности — `DATA-SOURCES.md`.
2. **Ядро не знает про React и рисование.** Всё, что считает, лежит в `src/core/`
   и проверяется Vitest без DOM. Интерфейс только показывает.
3. **Миллиметры и граммы.** Внутри всё в мм и г; дюймы, board feet, килограммы
   и рубли — только на выходе, `units` в рецепте это про отображение, не про модель.
4. **Нельзя нарисовать неизготовимое.** Модель данных — не картинка, а рецепт
   производственных операций. Разрешены только те операции, которые существуют
   на верстаке; узор, раскрой, отходы и себестоимость — его проекции.

## Слои

```
i18n/          словарь. Данные, не импортирует ничего из проекта
   ↓
core/          чистые функции над Recipe и Mosaic: математика, раскрой,
               влажность, экономика, лицензия. Ни одного обращения к document
   ↓
render/        отрисовка в Canvas 2D: доска, мозаика, 3D, текст, картинка
   ↓
*.tsx          панели, студия, печатные листы. Читают состояние, зовут core, рисуют
   ↓
App.tsx        сборка: состояние рецепта, история, режимы, маршрутизация по URL
```

Стрелка идёт только вниз. `core/` не импортирует `.tsx` и `render/`.
Потянуло импортировать компонент из ядра — расчёт написан не там.

Исключение одно и оно осознанное: несколько модулей ядра (`favorites.ts`,
`stock.ts`, `economics.ts`, `workshop.ts`) читают `localStorage`. Это не DOM
и не React, тестами накрывается, но помнить стоит: чистые они не полностью.

## Состояние

Единственный источник истины — `recipe` в `App.tsx` (режим «Рецепт») и `mosaic`
в `MosaicStudio.tsx` (режим «Мозаика»). Шины событий нет и не нужно: пересчёт
идёт через `useMemo` от состояния, React сам решает, что перерисовать.

История правок — `useHistoryState.ts`, глубина 60 шагов, правки подряд
склеиваются в одну запись, чтобы перетаскивание планки не съедало всю отмену.

Автосохранение — `localStorage`, с прогоном через `sanitize.ts`: в хранилище
мог попасть чужой рецепт из ссылки в прошлый визит.

## Board DNA

Весь проект едет в `#dna=` (`share.ts`, `mosaicShare.ts`): base64url от JSON.
Три решения, которые стоит помнить:

- **UTF-8 → base64url напрямую**, а не `btoa(encodeURIComponent(s))`: второй
  вариант раздувал каждую кириллическую букву втрое, и ссылка с русскими
  названиями пород переваливала за 3500 символов — такие URL режут мессенджеры.
- **В ссылку едут только использованные породы** и только поля, которые
  пользователь мог изменить. Справочное (латинское название, твёрдость, усушка,
  источник) восстанавливается из каталога по `id`.
- **Вход из ссылки — недоверенный.** Всё, что приходит извне, идёт через
  `sanitize.ts` до того, как попасть в состояние. Это не паранойя: без него
  ссылка вешала вкладку получателя и сообщала отправителю, что её открыли
  (`README.md`, раздел безопасности).

## Каталог пород

`core/defaults.ts` — семь пород. Плотность, твёрдость по Янка и усушка сверены
поштучно по The Wood Database, у каждой записи `source` с датой. На этих числах
считается движение древесины, поэтому вписывать их по памяти нельзя — только
со сверкой. Цена — рыночный ориентир, справочной величиной не является.

Как добавлять породу — `DATA-SOURCES.md`.

## Локализация

`core/i18n.ts` + `i18n/ru.ts`. Ключи типизированы формой русского словаря:
опечатка в ключе — ошибка компиляции, а не пустое место на экране.

**Правило: новая строка, видимая пользователю, идёт через словарь.** Старые
строки не переносим — это отдельная работа, и она не приближает продажу.
Значит, в проекте будет период, когда часть строк в словаре, а часть в JSX;
это осознанный долг, а не недосмотр.

## Платный слой

Бесплатное и платное разделены не по коду, а по функциям: проектирование,
расчёт, раскрой и инструкция для цеха бесплатны всегда. Ключом открывается
то, что привязано к бизнесу мастерской — профиль и бренд, заказы, партии,
коммерческое предложение, паспорт изделия, склад, журнал факта.

Проверка ключа офлайн, без бэкенда. Провал проверки роняет в бесплатный режим
**молча**: сломанная проверка не должна останавливать работу в цеху.

## Проверки

```bash
npm test      # Vitest
npm run lint  # oxlint
npm run build # tsc -b && vite build
```

Тесты в CI не для красоты: workflow `.github/workflows/pages.yml` публикует
на GitHub Pages только то, что их прошло.

Что тесты держат на самом деле (всё это уже случалось или могло случиться):
эталонный кейс раскроя, пять контрольных точек таблицы EMC, поведение
на мусорном входе (NaN, Infinity, пустое поле), чужую ссылку, которая вешала
вкладку, генератор, у которого объявленная ручка ни на что не влияла,
раскрой, где детали накладывались друг на друга.

## Прод-сборка

`vite.config.ts` собирает с `base: './'` — без этого пути на `/assets/`
резолвились бы от корня домена, а не от `/endgrain/`.

CSP и политика реферера ставятся мета-тегами в прод-сборку, а не заголовками
сервера: GitHub Pages свои заголовки настраивать не даёт, а мета-тег едет
вместе со статикой и не разъезжается с кодом. В URL лежит Board DNA, то есть
весь проект пользователя, и без политики реферера он уезжал бы в `Referer`
целиком.

Прод-зависимости — `react` и `react-dom`, и это стоит защищать: бандл
103 КБ gzip. Библиотека ради одной функции здесь дороже, чем она выглядит.
